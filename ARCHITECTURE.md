## 🗄️ Database Architecture

### Why PostgreSQL + pgvector?

Traditional approach:
- PostgreSQL for user data
- Separate vector DB (Pinecone, Weaviate)
- More deployment complexity ❌

Our approach:
- PostgreSQL 16 with pgvector extension
- One database for everything ✅
- Simpler, more reliable, transaction support

### Schema Overview

```
Users ─┬─→ Documents ─┬─→ DocumentChunks (with embeddings)
       │              └─→ Permissions
       ├─→ SearchQueries (analytics)
       ├─→ ConversationSessions ─→ ConversationMessages
       └─→ AuditLogs
```

### Vector Embeddings

Each document chunk stores a **1536-dimensional vector**:

```python
embedding: Vector(1536)  # Standard embedding size
```

These are generated by Ollama and indexed using **IVFFlat**:

```sql
CREATE INDEX idx_document_chunks_embedding 
ON document_chunks 
USING ivfflat (embedding vector_cosine_ops)
```

**Why 1536 dimensions?**
- Most embedding models use this size (OpenAI, Ollama, etc.)
- Good balance: expressive enough + not too slow
- If you switch LLMs, just adjust this number

## 🔐 Authentication & Authorization

### JWT Flow (Current)

```
Client                         Backend
  │                               │
  ├─→ POST /api/v1/auth/token ─→ │
  │                               ├─ Generate JWT
  │                               ├─ Generate Refresh Token
  │   ← {access_token, refresh_token} ←─ │
  │
  ├─→ GET /api/v1/documents ──→  │
  │   + Authorization: Bearer <token>
  │                               ├─ Verify JWT
  │                               ├─ Extract user_id
  │   ← [list of documents] ←─ │
```

**Token Structure:**
```json
{
  "sub": "user-uuid",           // Subject (who)
  "exp": 1707123456,            // Expiration
  "iat": 1707120456,            // Issued at
  "type": "access"              // "access" or "refresh"
}
```

### Keycloak Integration (Phase 5)

When integrated, the flow becomes:

```
Client                    Keycloak              Backend
  │                          │                      │
  ├─→ Login ──────────────→  │                      │
  │                          ├─ Validate creds      │
  │   ←── OAuth Code ────────┤                      │
  │                                                 │
  ├─→ Exchange code ─────────────────────────────→ │
  │                                    ├─ Verify with Keycloak
  │   ← Access Token (from Keycloak) ←─ │
```

**Advantages of Keycloak:**
- LDAP/Active Directory support
- Multi-factor authentication
- Social login (Google, GitHub, etc.)
- Audit logging built-in
- Delegated access management

## 🎯 Backend Architecture (FastAPI)

### Request Flow

```
HTTP Request
    ↓
Middleware (CORS, TrustedHost)
    ↓
Route Handler (e.g., @router.post("/documents"))
    ↓
Database Session (async, with context manager)
    ↓
Dependency Injection (Depends(get_db))
    ↓
Pydantic Validation (Input schema)
    ↓
Business Logic (Service layer - todo)
    ↓
ORM Operations (SQLAlchemy)
    ↓
Pydantic Serialization (Output schema)
    ↓
JSON Response
```

### Why Async?

Without async:
```python
@app.get("/documents")
def list_documents():  # Thread-per-request
    docs = db.query(Document)  # Blocking!
    return docs
# Server blocks while waiting for DB
```

With async:
```python
@app.get("/documents")
async def list_documents(db = Depends(get_db)):  # Coroutine
    stmt = select(Document)
    result = await db.execute(stmt)  # Non-blocking
    return result.scalars().all()
# Server can handle other requests while waiting
```

**Result:** 10x more concurrent users with same hardware.

## 🤖 AI Service Architecture

### Local LLM Setup (Ollama)

```
Your Backend
    ↓
AI Service (FastAPI wrapper)
    ↓
Ollama (Container with Llama2-7B loaded in memory)
    ↓
Response
```

### Embedding Pipeline

**When uploading a document:**

```
1. Parse PDF/TXT
   └→ ["chunk 1", "chunk 2", "chunk 3", ...]

2. For each chunk:
   a. Send to Ollama embedding endpoint
   b. Get 1536-dimensional vector
   c. Store in PostgreSQL with pgvector

3. Store metadata:
   - Document ID
   - Chunk index
   - Page number
   - Section heading
```

### RAG (Retrieval Augmented Generation)

**When user asks a question:**

```
1. User: "How do we handle authentication?"

2. Embed the question
   └→ [0.12, 0.34, ..., 0.56]  // 1536 dims

3. Search for similar chunks (cosine similarity)
   SELECT * FROM document_chunks
   ORDER BY embedding <-> question_embedding
   LIMIT 5
   └→ Returns top 5 relevant chunks

4. Format as prompt:
   "Given this context: [chunks]
    Answer this question: How do we handle authentication?"

5. Send to Llama2 via Ollama

6. Return response with citations:
   "Based on the authentication documentation,
    we use JWT tokens with 30-minute expiration..."
```

## 🐳 Docker Compose Orchestration

### Service Dependencies

```
postgres ← (required by all)
  ↑
  ├─ backend
  ├─ keycloak
  └─ (initialized at startup)

redis ← (cache, sessions)
  ↑
  └─ backend

ollama ← (LLM provider)
  ↑
  └─ ai-service

ai-service ← (called by backend for embeddings)
  ↑
  └─ backend

keycloak ← (OAuth provider)
  ↑
  └─ backend
  └─ nginx

nginx ← (reverse proxy)
  ↑
  ├─ backend
  ├─ keycloak
  └─ frontend (future)
```

### Network Communication

All services communicate over a **Docker bridge network** (`knowledge-network`):

```
Backend → Database: tcp://postgres:5432
Backend → Redis: tcp://redis:6379
Backend → Ollama: http://ollama:11434
Backend → Keycloak: http://keycloak:8080
Backend → AI Service: http://ai-service:8001
```

**No port mapping needed between containers** (except for external access).

## 🔒 Security Layers

### 1. Container Isolation

Each service runs in its own container with restricted permissions:
```dockerfile
# Backend can't directly access Keycloak database
# Each service has specific network access
```

### 2. Environment Variables

Sensitive data in `.env`:
```
POSTGRES_PASSWORD=actual_password  # Not in code
SECRET_KEY=your_jwt_secret_here    # Not in code
```

### 3. Database-level Security

```sql
-- Keycloak users only access auth tables
-- Backend users only access their own documents
SELECT * FROM documents WHERE owner_id = current_user_id
```

### 4. JWT Tokens

```python
# 30-minute expiration (short-lived)
# Refresh tokens for longer sessions
# Cryptographically signed (HS256)
```

### 5. CORS & Trusted Hosts

```python
# Only frontend can call API
CORSMiddleware(allow_origins=["localhost:3000"])
# Only expected hosts accepted
TrustedHostMiddleware(allowed_hosts=["localhost"])
```

## 📊 Data Flow Examples

### Example 1: Upload a Document

```
┌─ Frontend (React)
│   POST /api/v1/documents/upload
│   - Select PDF file
│   - Add title & description
│
├─ Nginx (reverse proxy)
│   Forward to backend:8000
│
├─ Backend (FastAPI)
│   1. Verify JWT token
│   2. Validate file size (< 50MB)
│   3. Store file: /app/documents/{uuid}.pdf
│   4. Create Document record in DB
│   5. Queue background task: "process_document"
│   6. Return: {id, status: "pending"}
│
└─ Background Task (Celery - future)
    1. Extract text from PDF
    2. Split into chunks (~512 tokens)
    3. For each chunk:
       a. Call AI Service: POST /embed
       b. Receive 1536-dim vector
       c. Insert into document_chunks
    4. Update Document: status = "completed"
    5. Log in audit_logs
```

### Example 2: Search Question

```
┌─ Frontend
│   POST /api/v1/search/rag
│   {"query": "How do I upload documents?"}
│
├─ Backend
│   1. Verify JWT
│   2. Call AI Service: POST /embed
│   3. Get query_embedding (1536 dims)
│   4. Execute SQL:
│      SELECT * FROM document_chunks
│      ORDER BY embedding <-> query_embedding
│      LIMIT 5
│   5. Retrieve top 5 chunks:
│      - chunk_1: "To upload, click the Upload button..."
│      - chunk_2: "Supported formats: PDF, TXT..."
│      - ...
│   6. Format prompt:
│      "Context:\n{chunks}\n\nQuestion: {query}"
│
├─ AI Service
│   POST /generate
│   Call Ollama with prompt
│
├─ Ollama (Llama2-7B in memory)
│   Generate streaming response:
│   "To upload a document, follow these steps..."
│
└─ Backend → Frontend
    Streaming response with citations
```

## 🎓 Key Learnings from Phase 1

1. **Async is critical** for modern APIs (especially AI workloads)
2. **One database > multiple databases** for simplicity (at this scale)
3. **Vector embeddings need fast indexing** (IVFFlat, HNSW)
4. **Separation of concerns** makes code testable
5. **Environment-based config** for flexibility
6. **Docker Compose** enables dev ≈ production
