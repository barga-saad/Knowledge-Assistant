                           PROJECT OVERVIEW
================================================================================

A production-ready full-stack application demonstrating modern software 
engineering practices with AI integration. This is an enterprise-grade Q&A 
platform that uses local AI (Ollama/Llama2-7B) for semantic search and 
document analysis.

KEY FEATURES:
- AI-powered semantic search using vector embeddings
- Document management and processing
- Conversational Q&A with Retrieval-Augmented Generation (RAG)
- Enterprise authentication with Keycloak SSO
- Full-stack architecture with microservices

                     KEY DECISIONS & RATIONALE
================================================================================

1. PostgreSQL + pgvector instead of separate vector DB
   WHY: Simpler deployment, ACID transactions, single source of truth
   TRADE-OFF: Less specialized than dedicated vector DBs

2. Async FastAPI over Django
   WHY: 10x better concurrency, modern async/await, automatic docs
   TRADE-OFF: Steeper learning curve

3. Local Llama2-7B over OpenAI API
   WHY: Privacy (data stays local), cost-effective, no API dependencies
   TRADE-OFF: Slower inference, requires GPU/good CPU

4. Keycloak for authentication
   WHY: Enterprise-ready (LDAP, SSO, MFA), open-source, scalable
   TRADE-OFF: More complex setup than simple JWT

5. Docker Compose for local development
   WHY: Dev environment ≈ production, prevents "works on my machine"
   TRADE-OFF: Requires Docker installation

6. IVFFlat vector indexing
   WHY: Fast approximate search, good speed/accuracy tradeoff
   TRADE-OFF: Not 100% accurate, must tune params

ERRORS ENCOUNTERED DURING DOCKER COMPOSE UP (March 2, 2026):

1. **Keycloak startup failure** (initial run):
   - Warning: unable to obtain JDBC connection.
   - Cause: `java.net.UnknownHostException: postgres` – Keycloak was pointing at
     hostname `postgres` which did not correspond to the service name. This was
     corrected and the error disappeared on restart.
   - Secondary symptom: repeated `role "root" does not exist` errors from
     PostgreSQL while Keycloak attempted to connect using default credentials.

2. **PostgreSQL error logs** (persistent):
   - After restarting, Postgres still logged `FATAL: role "root" does not exist`
     at ~10‑second intervals.
   - Investigation revealed the **healthcheck command** of the Postgres service
     was the culprit. It runs `pg_isready -h localhost` inside the container,
     which by default uses the OS user (`root`) as the Postgres role. Since no
     `root` user exists, each healthcheck produced a fatal message.

INVESTIGATION & FIXES:
- Checked `.env` variables and confirm POSTGRES_USER is set to `postgres`.
- Inspected `docker-compose.yml`:
  ```yaml
  healthcheck:
    test: ["CMD-SHELL", "pg_isready -h localhost"]
  ```
- Solution: modify the healthcheck to specify the correct user or set
  `PGUSER=postgres`.

EXAMPLE UPDATED HEALTHCHECK:
```yaml
  healthcheck:
    test: ["CMD-SHELL", "pg_isready -h localhost -U postgres"]
    interval: 10s
    timeout: 5s
    retries: 5
```

NEXT ACTIONS:
- Apply the healthcheck change in `docker-compose.yml`.
- Re-launch the stack and verify the fatal messages stop.
- Proceed with Phase 2 tasks once the environment is stable.
